# Typography

## Font families

[//]: # (tokens:font)

| Token | Value | For |
| --- | --- | --- |
| `--helix-font-sans` | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif` | Everything, unless it is one of the two below. |
| `--helix-font-mono` | `ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace` | Code, and anything that has to line up in a column. |
| `--helix-font-display` | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif` | Headings meant to be looked at rather than read. Falls back to the sans face. |

[//]: # (/tokens)

Helix has three font families and no scale of weights and widths. A design
system with more families than a product uses ends up with two that mean the
same thing.

## The type scale

The type scale runs from `--helix-text-xs` to `--helix-text-3xl`.
`--helix-text-control` sets the size of a control's own text. It follows the
region's density and is separate from the type scale.

**The base layer applies the scale to heading elements.**

```css
:where([data-prose] h1) { font-size: var(--helix-text-3xl); }
:where([data-prose] h2) { font-size: var(--helix-text-2xl); }
```

Because the styles target the elements, a heading's markup and its appearance
match by default. The styles also reach prose that Helix does not render.
Content from a CMS, a Markdown file, or a rich-text field is styled correctly
inside `[data-prose]`, with no changes to the content.

Use `Text` when a heading's element and its appearance need to differ. A
section's second heading may need to look smaller and keep its place in the
outline. A `<p>` may need to look like a caption. `as` chooses the element, and
`variant` chooses the ramp:

```html
<helix-text
  as="h3"
  variant="body"
>Reads as body, outlines as a heading</helix-text>
```

By default the two match, so most headings need only `as="h2"`. CSS resolves
the match. `Text` does not write an attribute onto the host element, because
that would cause a hydration mismatch in every React app. Size, weight, and
leading are not properties. Each ramp already sets them, and setting them one
by one would allow a few hundred combinations, of which only a handful are
right. There is no separate `Heading` component, because `as` does that job.

## Style your own text

```html
<article data-prose>
  <h2>A real heading</h2>
  <p>Body text, at the right measure and leading.</p>
</article>
```

Put `[data-prose]` on the element that contains your text. Inside it, the token
layer styles headings, paragraphs, lists, links, and code.

For one-off text outside prose, use `[data-text]` to set the ramp:

```html
<span data-text="sm">Fine print</span>
```

## Line height, letter spacing, and weight

[//]: # (tokens:leading)

| Token | Value | For |
| --- | --- | --- |
| `--helix-leading-tight` | `1.2` | Body text set close, for a short measure. |
| `--helix-leading-normal` | `1.5` | Body text, and the default a paragraph takes. |
| `--helix-leading-loose` | `1.7` | Body text set open, for a long measure or a small size. |
| `--helix-leading-heading` | `calc(0.99em + 0.5rem)` | Headings, which want less than a paragraph. Written as a length plus an em so it tightens as the type grows. |

[//]: # (/tokens)

[//]: # (tokens:tracking)

| Token | Value | For |
| --- | --- | --- |
| `--helix-tracking-tight` | `-0.01em` | Large type, which needs the letters closer than a paragraph does. |
| `--helix-tracking-normal` | `0` | Body text, and the default. |
| `--helix-tracking-wide` | `0.02em` | Small capitals and labels, which need the room. |
| `--helix-tracking-wider` | `0.12em` | An uppercase eyebrow, which needs more room than a label. |

[//]: # (/tokens)

[//]: # (tokens:weight)

| Token | Value | For |
| --- | --- | --- |
| `--helix-weight-regular` | `400` | Body text, and the weight most of a page is set in. |
| `--helix-weight-medium` | `500` | A label, or a heading that should not shout. |
| `--helix-weight-semibold` | `600` | A heading, and the heaviest this system goes. |

[//]: # (/tokens)

**Headings have their own leading token.** At a paragraph's line height, a
heading looks loose at every size. The fix is not proportional, because larger
type needs less leading. `--helix-leading-heading` expresses that once, so no
heading level needs its own multiplier.
