# Iconography

```html
<helix-icon name="trash"></helix-icon>
```

108 glyphs, from Phosphor, drawn on a 256 box at Phosphor's bold weight. That is
Phosphor's own geometry and it is kept rather than rescaled: normalizing to a 24
box would change the optical weight of every glyph and stop the set matching
anything upstream. Bold rather than regular, because Phosphor's regular is a
hairline beside the medium weight this library sets its text in, and an icon
that reads lighter than the words next to it is the opposite of a mark.

## Size and color come from the context

An icon has no `size` and no `color` property. It is `1em` square and
`currentColor`, so it takes the size and color of the text it sits in:

```html
<span data-tone="danger">
  <helix-icon name="warning"></helix-icon> Careful
</span>
```

Inside a control, `--helix-size-icon` is what decides, and it follows the
region's density along with everything else. That is why an icon in a small
button is smaller without anybody saying so.

## Decorative or named

```html
<!-- Decorative: the text beside it already says what this is. -->
<helix-button>
  <helix-icon name="trash"></helix-icon>
  Delete
</helix-button>

<!-- Named: there is no text, so the icon has to carry the name. -->
<helix-icon-button
  label="Delete"
  name="trash"
></helix-icon-button>
```

An icon with no `label` is hidden from assistive technology, which is right when
the words are beside it and wrong when they are not. `Icon.Button` takes a
`label` because it never has words beside it.

## One that points along the line

```html
<helix-icon
  mirror
  name="arrow-right"
></helix-icon>
```

The names are physical, so `arrow-right` points right on every page. An arrow
that means forward or back asks with `mirror` to turn round on a right-to-left
page, which every caret the library draws already does.
[Localization](./localization) has the rest.

## Importing a glyph directly

```ts
import { trash } from '@fusion.dev/helix-icons'
```

Each glyph is data, `{ content, name, viewBox }`, so you can put one in your own
markup, in a canvas, or anywhere an element is not what you want. Every `name`
the library uses is held to the set of glyphs that actually exist, so a typo is a
build failure rather than an empty box.

**Hand one to the element and it draws it**, whatever set it came from:

```tsx
import { trash } from '@fusion.dev/helix-icons'

<helix-icon icon={trash} />
```

A property rather than an attribute, because an object is not a string: the
frameworks set properties and plain HTML cannot, which is what `name` is for.
Both set, the value wins.

**This is the door that scales.** `name` resolves through an index of the whole
set, which no bundler can shake, so a consumer who renders one named icon ships
all of it: 15 kB gzipped for 108 glyphs. A value ships the one glyph you
imported. It is also the door out of this set entirely, since anything exporting
that shape works, whether it is Phosphor at another weight, another library, or
your own drawings:

```ts
const dot = { content: '<circle cx="12" cy="12" r="10" fill="currentColor" />', name: 'dot', viewBox: '0 0 24 24' }
```

## Weight is a subpath

```ts
import { caretDown } from '@fusion.dev/helix-icons/regular'
import { trash } from '@fusion.dev/helix-icons/bold'
```

The default is bold, and `/bold` is the same set under a name that says so.

**A subpath rather than an attribute, because a weight is data rather than a
dial.** Phosphor's weights are outlined filled paths: `caret-down` is `a12,12`
at bold and `a8,8` at regular, so there is nothing for CSS to turn and every
weight offered is bytes shipped. A subpath is shaken per import site; a `weight`
attribute would put every weight into the index that `name` reads, taking one
consumer's 15 kB to about 90.

Only the default weight carries that index, so `name` draws bold. A consumer who
wants the set in another weight imports the values and hands them over.

## Adding one

Add the name to `helix/icons/icons.txt` and run `turbo run icons`. Phosphor names
resolve from `@phosphor-icons/core` at build time, so adding a glyph is adding a
line rather than hand-transcribing a path into a TypeScript object.

A mark Phosphor does not draw goes into `helix/icons/raw` as an SVG under the
same name, and is read from there when the package has no match. Keep it to the
same geometry, a 256 box at the bold weight: a glyph drawn at a different weight
is visible immediately when it sits beside one that was not.

## Icons this set does not have

Product marks. Helix and Cortex have marks and they live in the icon package,
but a mark is not an icon: it identifies a product and does not mean an action.
**A mark is one rounded body with material removed**, never a pictogram of a
metaphor, because the parent it stands beside is a geometric monogram. If you
are reaching for the icon set to draw a logo, that is the wrong drawer.
