# Surfaces and separation

**Separate each surface from what is behind it with exactly one of four
things.** The four are a fill, an edge, a lift, and space. A design language
leads with one of them. Helix uses an edge for surfaces on the page and a lift
for surfaces above it. A card has a hairline border and no shadow. A menu has a
shadow and no hairline border. The surface ladder below sets the ground color
for each place a surface can sit.

## The four ways to separate a surface

| | |
|---|---|
| **Fill** | A ground color different from what is behind it |
| **Edge** | A border |
| **Lift** | A shadow |
| **Space** | Nothing at all. The gap separates it |

When a design system uses two or three of these without a plan, a card can end
up with a border, a shadow, and a tint, each added by someone solving the same
problem again.

Helix sets the choice with two pairs of policy tokens:

[//]: # (tokens:separation-policy)

| Token | Value | For |
| --- | --- | --- |
| `--helix-border-surface` | `var(--helix-border-thin)` | The edge a surface in the flow takes. Zero to go shadow-first. |
| `--helix-shadow-surface` | `var(--helix-shadow-none)` | The lift a surface in the flow takes. None to go border-first. |
| `--helix-border-floating` | `0` | The edge a surface over content takes. |
| `--helix-shadow-floating` | `var(--helix-shadow-lg)` | The lift a surface over content takes. |

[//]: # (/tokens)

To make every component shadow-first, set the border pair to zero and give the
shadow pair a value. Reverse them to go border-first. Every Helix surface reads
both pairs, and this is checked. A surface that reads only one pair is easy to
miss. If it reads the shadow token and sets `border: none` directly, a theme can
change it in one direction and not in the other.

## The surface ladder

A surface's ground color token names where the surface sits:

[//]: # (tokens:surface-ladder)

| Token | Sample | For |
| --- | --- | --- |
| `--helix-color-background` | <span data-token-swatch style={{ background: 'var(--helix-color-background)' }} /> | The page. Told apart by nothing, because it is the ground. |
| `--helix-color-surface` | <span data-token-swatch style={{ background: 'var(--helix-color-surface)' }} /> | A plane on the page: a card, or a panel you own. Told apart by a fill, an edge or a lift, whichever the policy leads with. |
| `--helix-color-surface-raised` | <span data-token-swatch style={{ background: 'var(--helix-color-surface-raised)' }} /> | Lifted while still lying on the page: a selected tab, a hovered row. Told apart by its fill, which goes down the ramp rather than up. |
| `--helix-color-surface-overlay` | <span data-token-swatch style={{ background: 'var(--helix-color-surface-overlay)' }} /> | Over the page rather than on it: a menu, a popover, a dialog. Told apart by its shadow and by what it covers. |
| `--helix-color-surface-sunken` | <span data-token-swatch style={{ background: 'var(--helix-color-surface-sunken)' }} /> | A well a value goes into: an input, a track, a groove. Told apart by its fill, inward. |

[//]: # (/tokens)

**`raised` goes one step down the ramp.** A selected tab's pill, a hovered row,
and an option under the pointer all have the page on every side. Only their
fill separates them, and on a white page a fill has to be a step darker to be
seen. `overlay` works the other way. Its shadow and what it covers separate it,
so on a white page it is white.

## Using the page color inside a component

**`--helix-color-background` is the page color. Do not use it inside a
component.**

```css
/* Wrong. Claims the component is sitting on the page. */
.marker { background: var(--helix-color-background); }
```

Using the page color inside a component assumes the component sits on the page.
That is right only when the component is placed directly on the page.

`Timeline`'s marker had this mistake. It was painted the page color to hide the
rail behind it, so it came out darker than any surface other than the page. On a
card, it showed as a black disc. The sparkline's ring terminus had the same
mistake and looked the same.

Both looked correct for months, because components are usually built on the
page. The mistake shows on a card, a drawer, a toast, a panel, or a photograph,
and components are not built on any of those.

Put the color behind a hook that defaults to the page color. When the component
sits on another surface, the hook can be set to match. Helix requires this of
its own components, and the same applies to anything you build with it.

## Contrast

The theme engine measures each ink against the ground it is actually painted
on. The ladder records which pairs occur. For example, `foreground` on
`surface-overlay` is a real pair, and `foreground-on-accent` on `surface` is
not. See [Color](./color).
