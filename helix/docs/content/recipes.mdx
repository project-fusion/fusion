# Recipes

`@fusion.dev/helix-styles` includes recipes for markup that the components do
not render, such as:

- your own anchors
- your own buttons
- a card you built yourself
- prose from a CMS

Recipes are `data-` attributes. They need no JavaScript, and they use the same
tokens as the components. With recipes, your page can look like Helix without
any custom elements.

## Buttons

```html
<button
  data-button="solid"
  data-button-tone="primary"
>Save</button>
<a
  data-button="ghost"
  href="/settings"
>Settings</a>
```

A button recipe has two axes:

- `data-button` sets the button's emphasis: `solid`, `outlined`, `ghost`, or
  `subtle`.
- `data-button-tone` sets what the button means: `primary`, `accent`,
  `neutral`, or `danger`.

`data-button-width` takes `auto`, `standard`, or `full`.

**Use the button recipe only on elements that Helix does not render**, such as
an `<a>` styled as a button. For a button, use `helix-button`. The recipe has no
loading state, no pressed state, and no `type="submit"` handling.

## Links

```html
<a
  data-link
  href="/pricing"
>Pricing</a>
<a
  data-link
  data-link-underline="quiet"
  href="/docs"
>Docs</a>
```

`data-link-size` and `data-link-underline` are the modifiers. `quiet` is for
navigation, where an underline on every row would distract. If a link opens a
new tab or window, say so in the link text, so it does not surprise your users.

## Navigation items

```html
<helix-navigation label="Sections">
  <a aria-current="page" href="/guide">Guide</a>
  <a href="/api">API</a>
</helix-navigation>
<button data-navigation-item>Menu</button>
```

A link inside `helix-navigation` is styled by the page's stylesheet, because the
page's styles reach a slotted link before the component's do.
`data-navigation-item` gives the same look to an element outside a navigation
bar. Two custom properties set the text color:

- `--navigation-item-color` colors every destination except the current one.
- `--navigation-item-current-color` colors the destination marked
  `aria-current="page"`.

Set them on `helix-navigation` or on any element that contains it.

## Surfaces and layout

```html
<div data-card>…</div>
<li data-list-item>…</li>
<div data-dock="bottom-end">…</div>
```

`data-dock` pins an element to a corner of the window. `data-dock-within` pins it
to a corner of the nearest positioned ancestor.

## Surface axes

Two of the [visual axes](./visual-axes) describe a surface. Use these attributes
to apply them to a plain element:

```html
<section data-material="glass">…</section>
<div data-separation="elevated">…</div>
```

`data-material` takes `glass`, `frosted`, and `transparent`. `data-separation`
takes `elevated`, `filled`, `outlined`, and `plain`. The values are the same as
the axes' values, so each word means the same thing here as on a component. A
`<section>` that is `glass` and a component with `material="glass"` get the same
treatment. See [Elevation and material](./elevation-and-material).

**Blur costs the most to render.** `glass` and `frosted` both use a
`backdrop-filter`. The compositor re-reads what is behind the element on every
frame in which the element moves. A full-width band that stays on screen while
you scroll pays that cost the whole time. To show depth, use `data-separation`,
which costs less.

## Prose

```html
<article data-prose>
  <h2>From a CMS</h2>
  <p>Styled without being rewritten.</p>
</article>
```

In prose:

- Headings use the type scale.
- Paragraphs use the measure and leading.
- Lists, links, and inline code follow the same styles.

See [Typography](./typography).

Three Markdown constructs need components, because HTML alone cannot hold what
they need:

- **Fenced code** becomes `helix-code-block`, with the fence's language as its
  `label`. A `<pre>` has no label or copy button.
- **Alerts** such as `> [!WARNING]` become `helix-callout`. A `<blockquote>` has no
  tone. `NOTE` becomes `tone="info"`, `TIP` becomes `success`, `WARNING` becomes
  `warning`, and `CAUTION` becomes `danger`. `IMPORTANT` has no tone. Each
  callout is headed by its kind, as GitHub shows it.
- **Tables** become `helix-table`. A `<table>` squeezes its columns to fit, so
  a narrow screen breaks a value such as `eu-central-1` across lines. The
  header row becomes the table's columns, each aligned as the Markdown aligned
  it. A column of short values stays whole, a column of sentences wraps, and a
  table wider than the screen scrolls in its own box.

The `rehype` plugin from `@fusion.dev/helix/rehype` makes all three changes in the
tree your Markdown library has already built. It parses nothing, so your
library, its dialect, and your sanitizing stay yours. Add it to any pipeline
that reaches rehype, such as `remark` with `remark-rehype`, `react-markdown`, or
MDX:

```js
import rehypeHelix from '@fusion.dev/helix/rehype'

const html = await unified()
  .use(remarkParse)
  .use(remarkRehype)
  .use(rehypeHelix)
  .use(rehypeStringify)
  .process(markdown)
```

Code that a highlighter colored before the plugin ran keeps its colors. Pass
`fences: false` if your page draws its own code blocks, `alerts: false` to keep
alerts as quotes, `tables: false` to keep tables as HTML, and `headings` to
name each kind in your page's language. A table with a caption, a cell that
spans more than one column or row, or a heading cell outside its header row
stays HTML, because the grid cannot draw it as written.

> [!NOTE]
> The plugin changes only these three constructs. If the Markdown comes from your
> users, sanitize it in your pipeline before the plugin runs.

Prose spaces each component the same as the element it replaces.

## Region axes

These two attributes are API. Import the base layer for them, even in an app
that uses only components:

```html
<div data-density="sm">…</div>
<div data-color-mode="dark">…</div>
```

`data-density` sets the size of the controls in a region. It works through
custom properties, so it crosses every shadow boundary. `data-color-mode` sets
the color mode for a subtree. See [Size and
density](./size-and-density) and [Color modes](./color-modes).

## Utilities

```html
<span data-hidden-visually>Sorting by</span>
```

`data-hidden-visually` clips the element, so it stays in the accessibility tree.
`display: none` would remove it. See [Accessibility](./accessibility).

## When to use a component

A recipe sets appearance and has no behavior. A recipe cannot:

- manage state
- take part in a form
- trap focus
- handle the keyboard

If you need to add a script to a recipe, use the component.
