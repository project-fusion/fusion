# Recipes

`@fusion.dev/helix-styles` includes recipes for markup that the components do
not render, such as:

- your own anchors
- your own buttons
- a card you built yourself
- prose from a CMS

Recipes are `data-` attributes. They need no JavaScript, and they use the same
tokens as the components. With recipes, your page can look like Helix without
any custom elements.

## Buttons

```html
<button
  data-button="solid"
  data-button-tone="primary"
>Save</button>
<a
  data-button="ghost"
  href="/settings"
>Settings</a>
```

A button recipe has two axes:

- `data-button` sets the button's emphasis: `solid`, `outlined`, `ghost`, or
  `subtle`.
- `data-button-tone` sets what the button means: `primary`, `accent`,
  `neutral`, or `danger`.

`data-button-width` takes `auto`, `standard`, or `full`.

**Use the button recipe only on elements that Helix does not render**, such as
an `<a>` styled as a button. For a button, use `helix-button`. The recipe has no
loading state, no pressed state, and no `type="submit"` handling.

## Links

```html
<a
  data-link
  href="/pricing"
>Pricing</a>
<a
  data-link
  data-link-underline="quiet"
  href="/docs"
>Docs</a>
```

`data-link-size` and `data-link-underline` are the modifiers. `quiet` is for
navigation, where an underline on every row would distract. If a link opens a
new tab or window, say so in the link text, so it does not surprise your users.

## Surfaces and layout

```html
<div data-card>…</div>
<li data-list-item>…</li>
<div data-dock="bottom-end">…</div>
```

`data-dock` pins an element to a corner of the window. `data-dock-within` pins it
to a corner of the nearest positioned ancestor.

## Surface axes

Two of the [visual axes](./visual-axes) describe a surface. Use these attributes
to apply them to a plain element:

```html
<section data-material="glass">…</section>
<div data-separation="elevated">…</div>
```

`data-material` takes `glass`, `frosted`, and `transparent`. `data-separation`
takes `elevated`, `filled`, `outlined`, and `plain`. The values are the same as
the axes' values, so each word means the same thing here as on a component. A
`<section>` that is `glass` and a component with `material="glass"` get the same
treatment. See [Elevation and material](./elevation-and-material).

**Blur costs the most to render.** `glass` and `frosted` both use a
`backdrop-filter`. The compositor re-reads what is behind the element on every
frame in which the element moves. A full-width band that stays on screen while
you scroll pays that cost the whole time. To show depth, use `data-separation`,
which costs less.

## Prose

```html
<article data-prose>
  <h2>From a CMS</h2>
  <p>Styled without being rewritten.</p>
</article>
```

In prose:

- Headings use the type scale.
- Paragraphs use the measure and leading.
- Lists, links, and inline code follow the same styles.

See [Typography](./typography).

If you control the Markdown renderer, map two elements to components, because
HTML alone cannot hold what they need:

- **Fenced code** to `helix-code-block`, with the fence's language as its `label`.
  A `<pre>` has no label or copy button.
- **Alerts** such as `> [!WARNING]` to `helix-callout`. A `<blockquote>` has no
  tone. `NOTE` and `IMPORTANT` become `tone="info"`, `TIP` becomes `success`,
  `WARNING` becomes `warning`, and `CAUTION` becomes `danger`.

Prose spaces each component the same as the element it replaces.

## Region axes

These two attributes are API. Import the base layer for them, even in an app
that uses only components:

```html
<div data-density="sm">…</div>
<div data-color-mode="dark">…</div>
```

`data-density` sets the size of the controls in a region. It works through
custom properties, so it crosses every shadow boundary. `data-color-mode` sets
the color mode for a subtree. See [Size and
density](./size-and-density) and [Color modes](./color-modes).

## Utilities

```html
<span data-hidden-visually>Sorting by</span>
```

`data-hidden-visually` clips the element, so it stays in the accessibility tree.
`display: none` would remove it. See [Accessibility](./accessibility).

## When to use a component

A recipe sets appearance and has no behavior. A recipe cannot:

- manage state
- take part in a form
- trap focus
- handle the keyboard

If you need to add a script to a recipe, use the component.
