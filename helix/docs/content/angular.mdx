# Angular

Angular does not compile a template that contains a tag it does not recognize.
To use Helix components, add `CUSTOM_ELEMENTS_SCHEMA` to the components that
render them.

```ts
import { CUSTOM_ELEMENTS_SCHEMA, Component } from '@angular/core'

@Component({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  standalone: true,
  template: `<helix-button>Save</helix-button>`,
})
export class SaveButton {}
```

If you can, declare the schema only on the components that use Helix.
`CUSTOM_ELEMENTS_SCHEMA` turns off unknown-element checking for the whole
template it is on. A narrow scope keeps that check, which catches your own
typos, in your other components.

## Bind properties and events

```html
<helix-input
  (change)="name = $event.target.value"
  [value]="name"
/>
```

`[prop]` sets a property, which a value that is not a string needs. `(event)`
binds with `addEventListener`, so use the event's own name.

**Do not use `attr.` for a stateful property.** `[attr.value]="name"` writes the
attribute. The attribute seeds the control and is out of date as soon as someone
types in it. The property holds the current value.

## No typings ship for Angular

The package has no `angular.d.ts`. `CUSTOM_ELEMENTS_SCHEMA` turns off the
checking that typings would feed, so Angular would not enforce a generated file.
We publish the manifest as `@fusion.dev/helix/custom-elements.json`, so you can
generate your own files from it.

As a result, a misspelled property fails without an error in Angular. In React,
Vue, and Svelte, the same mistake is a compile error. Check property names in
code review.

## Refuse a change

`value`, `open`, `checked`, and `active` are seeds. The element starts with the
value you set and then applies its own changes. To refuse a change, listen for
the `helix-before-*` event and call `preventDefault()`. See
[State and control](./state-and-control).
