# Browser support

Helix uses browser features directly, with no compatibility layer. It has no
polyfills, no transpiled fallback, and no setting that trades features for
support in older browsers. Your browser needs every feature Helix uses.

## What we test

We test in Chromium and WebKit, through Playwright, on Linux, with the network
blocked.

- The DOM specs run in both.
- The pixel baselines are captured in Chromium only.

WebKit is the engine in Safari, and the system webview a Tauri app draws with on
macOS and Linux. Playwright builds its own WebKit from the same source as
Safari, so a difference that only Safari shows can still get past our tests.

We do not run the tests in Firefox. The rest of this page lists the browser
features Helix uses. If you ship Helix to Firefox or Safari and find something
broken, please report it.

### What differs in WebKit

Checkbox Group, Radio Group, Option, Toast, and Tooltip name or describe their
host through `ElementInternals`, pointing into their own shadow root. WebKit
reads those references back as empty, so their specs for it fail there. We have
not yet checked whether VoiceOver still reads the name.

## Browser features Helix uses

| Feature | Where |
|---|---|
| Custom elements and shadow DOM | Everything |
| `ElementInternals` | Form participation, and ARIA that has to cross a shadow boundary |
| Popover API | Every overlay: menu, tooltip, select, combobox, dialog |
| `light-dark()` | Every color token, and each component color that differs between the modes |
| `oklch()` | Every color in the system |
| Relative colors, `oklch(from ...)` | The brand and accent ramps, the strong and subtle tones, and a few chart marks |
| `:has()` | Relational styling, mostly of slotted content |
| `@starting-style` | Entry transitions on overlays |
| `:state()` | Every boolean state the library publishes: `open`, `checked`, `selected`, `invalid`, `read`, `has-label`, `settled`, `empty`, `controls` |
| `CSS.highlights` | Filter-match highlighting, in `Command` and `Combobox` |
| Scroll-driven animations | The edge fade on a strip or table with more to scroll |

Positioning uses `@floating-ui/dom`. We chose this on purpose, and it is the one
place Helix takes a dependency for something the browser could do. CSS anchor
positioning is not yet available in every browser that has the rest of these
features.

## Which features set the minimum browser

**Check for `light-dark()`, relative colors, and the Popover API.** They are
the newest features Helix requires. Every token uses `light-dark()` to set both
color modes in one declaration. The brand and accent ramps are computed from
your seed colors with `oklch(from ...)`. Every overlay uses the Popover API to
draw in the top layer.

None of them has a useful fallback:

- A browser without `light-dark()` shows no color at all.
- A browser without relative colors draws no primary or accent color.
- A browser without the Popover API renders overlays in the page flow.

The first versions with all three are Chromium 123, Safari 18, and Firefox 128.

For that reason, this page has no support table with a fallback column. Helix
has no partial mode.

Chromium 132 has all three. We measured on September 15, 2026 that it
does not support two things your stylesheet can do through `::part()`:

- It ignores a range input's `::-webkit-slider-thumb` and
  `::-webkit-slider-runnable-track` after a part.
- It looks for the `@keyframes` that a `::part()` rule names inside the
  component's shadow root, so no animation starts.

The headless examples use neither.

`:state()` is the next newest feature. It does not set the minimum browser,
because components still work without it. A component that cannot record a
state keeps the look of its resting rule, so a checkbox is drawn unchecked.
Helix tests for `:state()` support in the one place that records states.

## Bundlers that rewrite `light-dark()`

**Set your bundler's CSS targets to browsers that have `light-dark()`.** Some
bundlers minify CSS for older browsers by default, and rewrite each
`light-dark()` into a fallback that resolves on the root element. The page
still switches between modes. A Toast, which takes the mode opposite the page,
and an element with its own `data-color-mode` both draw in the page's mode. A
development server does not minify CSS, so only a production build shows this.

We measured on November 3, 2026:

- Vite 8 targets Safari 16.4 by default and minifies with Lightning CSS, which
  rewrites every `light-dark()` call in `helix.css`. A Toast on a white page
  drew white.
- Next.js 16 targets Safari 16.4 by default, and Turbopack processes CSS with
  Lightning CSS.
- Bun 1.4 rewrites `light-dark()` when it bundles CSS, and has no setting for
  the browsers it targets. Serve the Helix stylesheets as files, as
  [Without a bundler](./without-a-bundler) shows.
- Angular builds CSS with esbuild, which leaves `light-dark()` as written.

The Helix templates set these targets. In Vite, set `build.cssTarget`:

```ts
import { defineConfig } from 'vite'

export default defineConfig({
  build: { cssTarget: ['chrome123', 'edge123', 'firefox128', 'safari18', 'ios18'] },
})
```

In Next.js, add `browserslist` to `package.json`:

```json
{
  "browserslist": ["chrome >= 123", "edge >= 123", "firefox >= 128", "safari >= 18", "ios_saf >= 18"]
}
```

## Browsers without `CSS.highlights`

`Command` and `Combobox` use the CSS Custom Highlight API to highlight the
matched text in their filtered results. Without it, the results still filter,
sort, and select correctly, and the match is not highlighted.

Nothing else in Helix uses it.

## Browsers without scroll-driven animations

Tabs, Navigation, Table, Data Table, and Log fade the edge that has more to
scroll past it. A scroll timeline drives the fade, and Safari added scroll
timelines in version 26. Firefox does not have them yet. In those browsers the
strip or table still scrolls, and its edges are cut flat with no fade.

## Older browsers

Helix does not support Internet Explorer and uses no polyfills. It has no
`browserslist`, no transpilation target, and no build flag for older browsers.
We decided this on purpose. Components that are custom elements cannot run in a
browser without custom elements, and every other feature in the table arrived in
the same generation of browsers.

To support an older browser, use the base layer. `@fusion.dev/helix-styles` is
plain CSS with no JavaScript. Markup built from its recipes works in much older
browsers than the components do. See [Without a bundler](./without-a-bundler).
