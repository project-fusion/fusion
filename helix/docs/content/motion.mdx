# Motion

## Duration and easing tokens

[//]: # (tokens:duration)

| Token | Value |
| --- | --- |
| `--helix-duration-instant` | `0ms` |
| `--helix-duration-fast` | `120ms` |
| `--helix-duration-normal` | `200ms` |
| `--helix-duration-slow` | `320ms` |
| `--helix-duration-turn` | `0.8s` |
| `--helix-duration-crawl` | `4s` |
| `--helix-duration-fade` | `120ms` |

[//]: # (/tokens)

[//]: # (tokens:easing)

| Token | Value |
| --- | --- |
| `--helix-easing-standard` | `cubic-bezier(0.2, 0, 0, 1)` |
| `--helix-easing-emphasized` | `cubic-bezier(0.3, 0, 0, 1.2)` |
| `--helix-easing-decelerate` | `cubic-bezier(0, 0, 0, 1)` |
| `--helix-easing-accelerate` | `cubic-bezier(0.3, 0, 1, 1)` |
| `--helix-easing-cycle` | `cubic-bezier(0.42, 0, 0.58, 1)` |
| `--helix-easing-spring` | `linear(0, 0.006, 0.025, 0.101, 0.539, 0.826, 0.976, 1.037, 1.043, 1.026, 1.006, 0.997, 1)` |

[//]: # (/tokens)

Helix has seven durations and six curves. `instant`, `fast`, `normal`, and
`slow` time a change that answers a hand. `fade` is the fade a panel keeps
while motion is reduced. `turn` is one revolution of a spinner, and `crawl` is
the same revolution while motion is reduced, so a busy ring still turns
slowly.

Use each curve for one kind of movement:

- `standard` for most movement
- `decelerate` for something arriving, such as a Dialog, a Drawer, or a Toast
- `accelerate` for something leaving
- `cycle` for a loop that repeats, such as a pulse or a loading sweep
- `emphasized` for a floating panel opening from its trigger, such as a
  Popover or a Menu, and for a marker that travels to a new place, such as the
  indicator under the selected tab
- `spring` for the few places where overshoot looks responsive and does not
  look like a bug

The theme engine takes a `motion` intent input. Use it to make every component
faster or slower at once.

## Each component handles reduced motion

The base layer has a global rule that caps animation and transition durations
when a user has asked for reduced motion. **The global rule does not apply
inside any component.**

```css
*, *::before, *::after { … }
```

The `*` selector does not cross a shadow boundary. The rule applies to your
prose, your layout, and the base layer's own recipes. It does not apply to any
component that draws inside a shadow root, which is almost every Helix
component. A custom property does cross that boundary, so under the setting
Helix takes its duration tokens down to almost nothing, and every transition
written with them stops. A component with an
animation of its own handles `prefers-reduced-motion` in its stylesheet.

The same applies to your own components. If you write a component with a shadow
root, the global rule does not cover it. This comes from how `*` works in CSS,
so it applies outside Helix too. It is the easiest accessibility regression to
ship without noticing.

```css
@media (prefers-reduced-motion: reduce) {
  :host {
    animation: none;
    transition: none;
  }
}
```

## What reduced motion changes

Some transitions show a relationship, such as a panel that slides out of the
control that opened it. Others are decorative, such as a floating effect. With
reduced motion, Helix removes decorative movement. It sets `fast`, `normal`,
and `slow` to 0.01ms, so a panel appears in its final place at once. The
transition still runs that long, so `transitionend` still fires. A Tooltip, a
Toast, and a panel that opens from a field or a Menu still fade in and out over
`fade`, 120ms, with no movement.

Anything that moves continuously without input stops completely:

- The aura shader
- Marquees
- The pulse loader
- The light on a `Border Beam`, whose edge is then lit steadily

The turning `Loader` slows to one turn every four seconds. A loader that stops
looks broken, and the turn still shows that work is in progress. The pending
ring on `IconButton` slows the same way.

## Pause the page's motion

Motion that starts by itself and runs longer than five seconds needs a way to
pause it, under WCAG 2.2.2. `Motion Toggle` pauses all of it on the page at
once, and a second press lets it run again:

```html
<helix-motion-toggle>Pause motion</helix-motion-toggle>
```

While the page's motion is paused:

- `Carousel` stops rotating under `autoplay`.
- `Video` pauses a video that started itself, and plays it again after.
- `Aura`, `Orb`, and `Strands` hold the frame they show.
- A graph that `connectGraph` lays out stops where its notes stand, and its
  three.js view stops turning.
- A map layer's `frames` stop on the frame they show.
- The 3D charts and `Heatmap` stand at their readings, and a growth or a move
  already running ends where it was heading.

The choice is the page's, held on the document element as
`data-helix-motion="paused"`. Set it in your markup to start the page paused,
or call `pauseMotion` from `@fusion.dev/helix-core`, and select on the
attribute to pause motion of your own:

```js
import { pauseMotion } from '@fusion.dev/helix-core'

pauseMotion()
pauseMotion(false)
```

With reduced motion set, `Carousel` and `Video` do not start by themselves,
and a graph lays out its notes with the drawing hidden, then shows them where
they settle.

A graph layout that runs past five seconds also offers its own button, in the
graph's frame, that stops it where the notes stand.

## Rows, tags, and items that move

When you sort, add, remove, or hide the rows of a `List`, the tags of a
`Tag.Group`, the items of a `Tree`, the rows of `Notifications`, or the entries
of a `Timeline`, each one slides from where it was to where it is now. A tree's branch carries its rows with it. A `Table` or a Data
Table that sorts moves its rows the same way, each row's cells together, and a
Data Table needs `row-key` to know a row across the change. A row, a tag, or an
item you add fades in. A list you render again with all new elements appears
at once.

Each family times the move from two hooks of its own, which the styled tier
sets from the tokens:

| Hook | Default |
| --- | --- |
| `--list-move-duration`, `--tag-group-move-duration`, `--tree-move-duration`, `--table-move-duration`, `--data-table-move-duration`, `--notifications-move-duration`, `--timeline-move-duration` | `--helix-duration-normal` |
| `--list-move-easing`, `--tag-group-move-easing`, `--tree-move-easing`, `--table-move-easing`, `--data-table-move-easing`, `--notifications-move-easing`, `--timeline-move-easing` | `--helix-easing-standard` |

Set them on the element to change one list, or on a selector to change many:

```css
helix-list {
  --list-move-duration: 320ms;
  --list-move-easing: var(--helix-easing-spring);
}
```

`0ms` turns the move off. The headless tier sets none of the hooks, so its
rows do not move until you set them. With reduced motion set, nothing moves,
even where a hook holds a duration of its own.

`Toast` makes room for a message and closes the gap after one in its own
stylesheet, so its stack has no hooks of this kind.

## The wash under the pointer

In `Navigation`, `Tabs`, and `Toggle Group`, the hover wash is one shape that
glides from item to item as a mouse or pen moves along the row, and fades out
when the pointer leaves. It takes the place of each item's own wash, in the
same color, from `--navigation-item-hover-background-color`,
`--tabs-tab-hover-background-color`, or
`--toggle-group-hover-background-color`. Arriving from outside the row, it
appears under the pointer without sliding. A touch draws no wash, and under
reduced motion the wash moves at once.

In `Menu`, the wash marks the row with focus, so it glides as the pointer or
the arrow keys move focus, and holds while the pointer crosses a divider. It
reads `--menu-item-hover-background-color`, and a `danger` row keeps its own
hue. A submenu that opens beside its row lights its own rows.

## Figures that count

A new `value` on a `Stat` or a `Trend` counts to the new number from the one
before. A screen reader reads only the new number. The count takes
`--stat-count-duration` or `--trend-count-duration`, `--helix-duration-slow` by
default, along `--stat-count-easing` or `--trend-count-easing`,
`--helix-easing-decelerate` by default, so the figure slows as it arrives.
`0ms` changes the figure at once, as reduced motion does. A figure you put in
the slot changes at once.

The number a `Progress` or a `Meter` shows under `show-value` counts the same
way, at the pace of the fill, from `--progress-count-duration` and
`--meter-count-duration`, which the styled tier sets from the fill's own
duration. A `Badge` whose count changes swells and settles over
`--badge-bump-duration`.

## Charts that follow their readings

When a chart's readings change, its marks move from the old readings to the
new: the bars of a `Bar Chart` and a `Sparkline`, the line and area of a
`Line Chart`, an `Area Chart` and a `Sparkline`, the slices of a
`Donut Chart`, and the points of a `Scatter Chart`. A `Heatmap` cell takes its
new color the same way. Every move uses `--helix-easing-decelerate`, which
never passes the value it is heading for, so no frame draws a reading the data
does not hold. The mark on the end of a line rides with it. Safari does not
transition a path's shape, so lines, areas, points, and the mark on a line's
end there take their new place at once.

Set `--chart-move-duration` and `--chart-move-easing` on a chart, or on an
element that holds several, to change how long the move takes and its curve.
They default to `--helix-duration-normal` and `--helix-easing-decelerate`, and
`0s` turns the move off. A `Line Chart` drawing its line on and an
`Area Chart` fading its wash in take 1.6 times the duration, as they take the
slow token beside the normal one, so `0s` stops them too. Under reduced
motion the marks take their new place at once, whatever duration you set.

## 3D charts that grow in and follow their readings

The 3D charts draw their own marks, in SVG and through three.js, so their
motion runs in script. They are `Spatial Bar Chart`, `Spatial Scatter Chart`,
`Spatial Ribbon Chart`, `Spatial Surface Chart`, `Spatial Treemap`, and
`Spatial Heatmap`. Each mark is known by its name, such as a bar's category
and series, and a new table is matched against the marks drawn:

- A mark both tables hold moves from its old reading to its new one, and
  slides to its new place.
- A mark only the new table holds grows from the floor.
- A mark the new table drops shrinks to the floor, and then goes.

The value axis eases to its new range, so a bar does not jump when the scale
changes, and its numbers are the new ones from the start. A surface whose grid
changed shape cannot be matched place for place, and takes its new shape at
once. A three.js drawing draws each frame the chart works out, and holds its
view still while the marks move.

A move takes `--<family>-move-duration` along `--<family>-move-easing`, such as
`--spatial-bar-chart-move-duration`. The styled tier sets them to
`--helix-duration-normal` and `--helix-easing-decelerate`, as the flat charts
move. The headless tier sets neither, so a new table is drawn at once there.

`grow` grows the marks in the first time the chart comes into view, each
category or column a little after the one before it, and `grow-again` grows
them again each time the chart comes back into view. The growth keeps its own
timing, a second for each mark, because the page asked for it by name. Under
`grow`, a later table grows the marks it adds the same way. A `Heatmap` takes
`grow` too: each cell starts empty and steps up through the tones to its own,
a column at a time. Its cells already take a new color through the
stylesheet, so it reads no move hooks.

## Starting styles and view transitions

Overlays use `@starting-style` to animate in. It sets a starting value and needs
no duration token of its own. The transition that runs from it uses the tokens
above.

Helix starts one view transition, when the page changes color mode. A view
transition draws the whole document twice and runs between the two pictures,
so a component that started one for its own sake would cancel the page's own,
or have its own canceled. The color mode belongs to the whole document, so
changing it is the one move that is the document's to make. `Theme Toggle` and
`setColorMode` from `@fusion.dev/helix-core` spread the new mode in a circle
from the button, wipe it across, or fade it, and change it at once under
reduced motion. Any other view transition is yours to start from your own
code, and the next section covers the one most sites want.

## Moving between pages

A site can move from one page to the next as a fade or a slide. Import the
page transition sheet after `helix.css`, on every page that takes part:

```css
@import '@fusion.dev/helix-styles/helix.css';
@import '@fusion.dev/helix-styles/page-transitions.css';
```

A link to another page on the same origin then fades the new page over the
old one, with no script, in browsers with cross-document view transitions.
Other browsers load the new page as before. The sheet stays out of `helix.css`
because the rule that turns it on speaks for the whole document and cannot be
scoped, so it is a site's choice to make. Under reduced motion the sheet turns
nothing on.

For a slide, write `data-page-transition="slide"` on the `html` element of the
page being arrived at. The new page comes in from the inline end and the old
one leaves toward the inline start. `slide-back` travels the other way, for a
step back, and right-to-left pages mirror both. The move takes
`--helix-duration-slow`.

A router that changes the page in place, without loading a new document,
calls `changePage` from `@fusion.dev/helix-core` around the change:

```ts
import { changePage } from '@fusion.dev/helix-core'

await changePage(() => router.show(next), { transition: 'slide' })
```

It names the way for the length of the move, changes the page at once under
reduced motion or where the browser has no view transitions, and rejects
where the change does. To keep a header still while the rest of the page
moves, give it a `view-transition-name` of its own on every page.

## Motion on your own elements

Four functions in `@fusion.dev/helix-core` give elements you write yourself
the motion Helix's own families have, with no component around them:

- `moveItems` slides the items of a list to their new places.
- `trackIndicator` sends one mark from item to item.
- `countTo` counts a figure to a new number.
- `followPointer` writes where a mouse or pen is over an element.

Each one works on any element, in any framework, and needs no Helix
stylesheet. Times and curves default to the tokens above, and to the values
those tokens hold where the page does not load them. Under reduced motion
nothing moves, the figure changes at once, and the pointer is not followed.
`moveItems`, `followPointer`, and `trackIndicator` return the way to stop.

### Items that move

`moveItems` watches an element's children. When you or your framework add,
remove, reorder, or hide them, each item slides from its old place to its new
one, and an item you add fades in:

```js
import { moveItems } from '@fusion.dev/helix-core'

const stop = moveItems(document.querySelector('#tasks'), {
  leaving: document.querySelector('#tasks-box'),
})
```

| Option | Default |
| --- | --- |
| `items`, a selector or a function returning the items | the element's children |
| `duration`, in milliseconds, as a time, or as a custom property | `--helix-duration-normal` |
| `easing`, a curve or a custom property | `--helix-easing-standard` |
| `leaving`, a positioned box around the element | none, so an item that leaves is gone at once |
| `arriveIntoEmpty`, so the first item into an empty list fades in | `false` |

A copy of an item that leaves fades out where it was, in the `leaving` box.
The copy never joins the element's own children, which your framework
manages, so give the box `position: relative` and put the list inside it.
When every item is new at once, as when a framework draws the whole list
again, the list appears without moving.

### A mark that travels

`trackIndicator` places one mark on the item that is marked now, and places it
again whenever an attribute inside the element changes, an item arrives or
leaves, or the element changes size:

```js
import { trackIndicator } from '@fusion.dev/helix-core'

trackIndicator(document.querySelector('nav'), {
  active: '[aria-current="page"]',
  indicator: document.querySelector('nav .mark'),
})
```

It writes four custom properties on the mark: `--indicator-x`,
`--indicator-y`, `--indicator-inline-size`, and `--indicator-block-size`.
Your stylesheet moves the mark with them, so its transition is the move:

```css
nav {
  position: relative;
}

nav .mark {
  block-size: var(--indicator-block-size, 0);
  inline-size: var(--indicator-inline-size, 0);
  inset-block-start: 0;
  inset-inline-start: 0;
  opacity: 0;
  position: absolute;
  transition:
    translate var(--helix-duration-normal) var(--helix-easing-emphasized),
    inline-size var(--helix-duration-normal) var(--helix-easing-emphasized),
    opacity var(--helix-duration-fast);
  translate: var(--indicator-x, 0) var(--indicator-y, 0);
}

nav .mark[data-placed] {
  opacity: 1;
}
```

`data-placed` is on the mark once it has a place, so it fades in where it
belongs. `data-moving` is on it while it travels. With nothing marked, the
mark loses `data-placed`. Call `place()` on what it returns after a change it
cannot see, such as a new stylesheet, and `stop()` to end it.

### A figure that counts

`countTo` counts the number an element shows to a new one, and resolves once
the new figure is written:

```js
import { countTo } from '@fusion.dev/helix-core'

await countTo(document.querySelector('#revenue'), 1284)
```

It counts from the number last counted to, or from the number the element's
text reads. Pass `from` the first time for a figure written with grouping in
another language. The figure is written in the element's language, or with
`format`, which takes the number and returns its text. The count takes
`--helix-duration-slow` along `--helix-easing-decelerate`, and a new count
started during one carries on from the figure drawn.

The element's text changes on every frame, so keep it out of a live region and
tell screen reader users the new number another way.

### Following the pointer

`followPointer` writes `--pointer-x` and `--pointer-y` on an element while a
mouse or pen is over it, each from -1 to 1, with 0 and 0 in the middle. A
right-to-left page mirrors `--pointer-x`. The two go when the pointer leaves,
so give them `0` as the fallback:

```js
import { followPointer } from '@fusion.dev/helix-core'

followPointer(document.querySelector('.card'))
```

```css
.card {
  rotate: x calc(var(--pointer-y, 0) * -6deg);
  transition: rotate var(--helix-duration-normal) var(--helix-easing-standard);
}
```

`data-following` is on the element while the two are written. A touch is not
followed, since a finger is on the element only while it presses. Pass `moved`
and `left` to hear the same positions in script.
