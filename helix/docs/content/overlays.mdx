# Overlays and layering

These components are overlays, and they all work the same way:

- `Dialog`
- `Drawer`
- `Popover`
- `Menu`
- `Select`
- `Combobox`
- `Tooltip`
- `Megamenu`
- `Speed Dial`
- `Command`
- `Tour`

Knowing how they work helps you avoid most overlay problems.

## Overlays render in the top layer

Every overlay uses the popover API, so the browser draws it in the top layer.
The top layer is above everything on the page, and these do not affect it:

- `z-index`
- `overflow: hidden`
- `transform`
- a stacking context in an ancestor

As a result, a menu inside a scrolling panel is not clipped, and a tooltip
inside a `transform`ed card is not trapped in its stacking context. You do not
configure a portal or pass `appendTo`, because the browser handles the layering.

**Do not raise an overlay with `z-index`.** It has no effect on a top-layer
element. If you want to use it, something else is wrong.

## How overlays are positioned

Overlays are placed with `@floating-ui/dom`, which does the following:

- It flips a panel to the other side of its anchor when there is no room below.
- It moves a panel placed beside its anchor below or above when there is no room
  on either side.
- It shifts a panel to stay on screen.
- It sizes a panel to the available space.

CSS anchor positioning is the platform's own way to do this. We do not use it
yet, because it is not available in every browser the rest of Helix supports.
See [Browser support](./browser-support).

While an overlay is open, its position is recomputed on scroll and resize. The
recomputing stops when the overlay closes.

## How overlays close

Light dismiss comes from the platform: click outside the overlay, or press
`Escape`. Helix makes light dismiss work correctly across shadow boundaries.

`document.activeElement` stops at the outermost host. Focus inside a shadow tree
is reported as the element that contains the tree. A simple check for whether
focus is still inside the overlay never matches, so the overlay would close as
soon as anything inside it is focused. Every way of closing an overlay in Helix
checks focus by walking through the shadow roots.

Nested overlays work because lifecycle events do not bubble.
`helix-before-open` and `helix-before-close` do not bubble and are not composed,
so a menu that closes inside a dialog does not close the dialog. `Escape` closes
the innermost overlay and leaves the others open.

## Where focus goes

A modal overlay keeps `Tab` inside itself while it is open, and it returns focus
to the element that opened it. `Dialog` and `Drawer` always do this. `Popover`
does it only in its modal mode.

**A tooltip never takes focus.** A tooltip only describes a control, so it
cannot contain a button. For something with a button in it, use a `Popover`.

## Keep an overlay open

An overlay sends `helix-before-close` before it closes. Cancel the event to keep
the overlay open:

```ts
dialog.addEventListener('helix-before-close', (event) => {
  if (unsaved) {
    event.preventDefault()
  }
})
```

Canceling covers `Escape`, a backdrop click, and the close button, because all
three send the same request. See [State and control](./state-and-control).

## Entry and exit animation

Overlays animate in with `@starting-style`. They animate out with a transition
on the `overlay` and `display` properties, which allows an exit animation on an
element the browser is about to remove from the top layer. Every overlay
responds to `prefers-reduced-motion`.

## Choose an overlay

| Component | Use it for |
|---|---|
| `Dialog` | A task that blocks the page |
| `Drawer` | The same, from an edge, usually larger |
| `Popover` | A surface anchored to a control, possibly interactive |
| `Tooltip` | A description of a control. Never interactive |
| `Menu` | A list of commands |
| `Select`, `Combobox` | A value chosen from a list, in a form |
| `Command` | A palette over the whole application |
| `Megamenu` | Navigation, anchored to a header |

A `Dialog` used for a tooltip's job traps focus for no reason. A `Tooltip` used
for a popover's job silently drops the button you put in it.
