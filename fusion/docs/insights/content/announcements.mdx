Fusion has five layers, and right now only the top one is usable. So that's
the one I'm finishing first: the interface layer. I'm shipping it as a design
system rather than a framework, because a design system is the part of an
interface a company can actually own.

## What it is

Every component is a custom element. It isn't a React component with wrappers
generated for everything else, and it isn't a kit of primitives you assemble
yourself. The element is what ships, and React, Vue and Svelte all use the same
one.

It comes in two tiers. The headless tier is behavior with no styles at all:
state, focus, keyboard, forms and accessibility. The styled tier is the same
components with a visual system on top. If you need different pixels, you drop
down a tier instead of copying a file, so a fork still has something supported
underneath it.

## What you get

You give it one brand color and it builds the whole palette, and it won't hand
you a palette it can't make readable. Contrast isn't an audit someone has to
schedule anymore. It's part of how the colors get made.

Every tag, property and event is in one manifest at a URL, and every page is
available as Markdown. I built that for agents before it was fashionable to say
so. A model reads the same page a person does, so there's no second, worse copy
of the API for either of them.

It's MIT licensed, it lives in your repository, and it keeps working whether or
not we're still involved. That's the test I hold every Fusion product to. If the
answer were no, it wouldn't be one.
