# Recall

Recall builds the context for each model call. A loop keeps its whole history,
and Recall chooses from it what fits the model's window. The trace's context
node records each part it placed and why, and each thing it dropped, so you can
see what the model saw.

## Pinned parts are never dropped

The rules, the task, and what the person said after the task are pinned. They
stay whole however full the window gets, because they are what a harness that
summarizes its history loses first.

| Part | Pinned | Example |
| --- | --- | --- |
| Rules | Yes | The system prompt and a project's rules |
| Task | Yes | "Fix the flaky checkout test" |
| Instruction | Yes | "Never touch the generated folder," said mid-session |
| Facts | No | What earlier sessions learned, from Engram |
| Turn | No | A model reply and the tools it called |
| Results | No | What those tools returned |
| Feedback | No | A check that failed |

## Compaction clears before it drops

When the history no longer fits, Recall works in order, and stops as soon as
the context fits:

1. The oldest tool results are cleared to one line each, which names the call.
   The call stays, so the model can make it again.
2. The oldest whole turns are dropped, each with what came back from it.
3. The facts from memory are dropped.

The latest turns stay whole. The context then gains one pinned summary, joined
to the task, that names what the dropped turns called and carries the loop's
own account of where the task stands. A later compaction replaces it.

[//]: # (rust:fusion-cortex-recall::assemble)

```rust
use fusion_cortex_core::provider::{Message, Role};
use fusion_cortex_recall::{assemble, Item, Part, Window};

let mut items = vec![
    Item::new(Part::Rules, Message::text(Role::System, "Never edit generated files."), "the rules"),
    Item::new(Part::Task, Message::text(Role::User, "fix the build"), "the task"),
];
for turn in 0..20 {
    items.push(Item::new(Part::Turn, Message::text(Role::Assistant, "x".repeat(400)), "a turn"));
    items.push(Item::new(Part::Feedback, Message::text(Role::User, "the build still fails"), "a check"));
}
let window = Window { tokens: 1_000, recent: 2, scale: 1.0 };

let context = assemble(&items, window, Some("Plan: 1 of 3 steps done."));

assert!(context.tokens <= 1_000);
assert_eq!(context.messages[0].joined(), "Never edit generated files.");
assert!(context.messages[1].joined().contains("Plan: 1 of 3 steps done."));
assert!(!context.dropped.is_empty());
```

## Sizes are estimates the provider corrects

Recall counts about four characters to a token. A loop compares that count with
the one its provider reports for the context it sent, and passes the ratio as
the window's scale, so the next estimate follows the model's own tokenizer.

[//]: # (rust:fusion-cortex-recall::estimate)

```rust
use fusion_cortex_core::provider::{Message, Role};

let message = Message::text(Role::User, "a".repeat(400));

assert_eq!(fusion_cortex_recall::estimate(&message), 108);
```

## Retrieval is a strategy

A scorer ranks Engram's facts against a query. `Overlap` counts the words a
fact shares with the query, leaving out common words such as `the` and `with`.
`Vector` compares the query's embedding with each
fact's, and `Weighted` combines the two, as the Scoring memory by meaning guide
describes. A fact that scores nothing still ranks, at half its confidence after
decay, because what a project's sessions learned is often about the project and
not the task.

`Selection` says how many facts to place and the least score each needs.
`Selection::top(8)` places up to eight with no floor. `.floor(0.3)` leaves out
every fact that scores below 0.3. `cortex ask` uses a floor of 0.3 where the
facts have vectors, and 0.1 by words alone. By words alone, a fact that shares
no word with the question scores zero, so the floor leaves it out. A vector
model gives every fact some similarity: `nomic-embed-text` gives a note on
another subject a cosine from 0.33 to 0.57, depending on the question, so a
floor leaves out only the facts furthest from it.

You pass the scopes the caller may read, and Recall places no fact outside
them, however well it scores. A scope matches only itself, so a caller that may
read the organization's facts reads a team's only when its scopes name that
team too. The Engram page describes the scopes.

[//]: # (rust:fusion-cortex-recall::relevant)

```rust
use fusion_cortex_engram::{Fact, Scope};
use fusion_cortex_recall::{relevant, Overlap, Selection};

let core = Scope::Team("core".into());
let facts = vec![
    Fact::new("the clock helper fixes the flaky checkout test", vec![], 0.8),
    Fact::new("the docs build with bun", vec![], 0.8),
    Fact::new("the core team fixes flaky tests on Fridays", vec![], 0.9).within(core),
];
let question = "fix the flaky checkout test";

let placed = relevant(&facts, &[Scope::Personal], question, &Overlap, Selection::top(2), |_| 0.0);
let above = relevant(&facts, &[Scope::Personal], question, &Overlap, Selection::top(2).floor(0.3), |_| 0.0);

assert_eq!(placed[0].0.content, "the clock helper fixes the flaky checkout test");
assert_eq!(placed.len(), 2, "the docs fact fills the last place");
assert!(placed.iter().all(|(fact, _)| fact.scope == Scope::Personal));
assert_eq!(above.len(), 1, "the docs fact shares only `the`, which Overlap leaves out");
```
